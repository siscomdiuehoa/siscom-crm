## 2. Phương án implementation cuối
**Kiến trúc:** NestJS module `customers` và `lookups`; Prisma cho truy vấn thường, truy vấn thô tham số hoá (`Prisma.sql`) **chỉ** cho tìm kiếm và khoá dòng; `prisma.$transaction` interactive cho mọi ghi, có `lock_timeout = 5s`, `statement_timeout = 15s`.
**Danh tính:** `ActorGuard` + `ACTOR_PROVIDER`; cấu hình thật = `DenyAllActorProvider` → mọi route (kể cả `GET`, `GET /lookups`) trả **401**; cảnh báo một dòng lúc khởi động.
**Hành vi chính (theo Contract rev.3):**
1. Tạo: kiểm DTO → giải mã lookup (mã → id, đúng loại, đang hoạt động) → `DEFAULT fn_next_customer_code()` → (nếu có `ownerId`) tạo phân công `OWNER` → audit; tất cả một transaction.
2. Sửa: khoá dòng khách → kiểm trạng thái → `updateMany` theo `version` → xử lý chủ sở hữu (đóng/mở phân công bằng giờ DB) → audit.
3. Danh sách: không tìm kiếm = `findMany`+`count`; có tìm kiếm = truy vấn inline tham số hoá + `count(*)` chính xác trong snapshot `REPEATABLE READ` (thử lại tối đa 2 lần khi `40001`).
4. Khôi phục: khoá dòng → `fn_customer_restore_conflicts` → cập nhật; xung đột MST ẩn/hiện thông tin theo phạm vi xem.
5. Liên hệ: khoá dòng khách trước; `isPrimary` hạ liên hệ chính cũ cùng transaction.
6. Xoá: route luôn 409 `DELETE_LINKS_UNVERIFIED`.
7. Lookup: chỉ đọc, 5 loại, chỉ mục đang hoạt động, không lộ `id`.
8. Lỗi: `DomainException` + ánh xạ lỗi Prisma/SQLSTATE; bộ lọc lỗi cộng thêm `error: { code, message, details? }`.
**Quyền:** `customer.read/create/update/delete/restore`, `contact.read/create`, `lookup.read`; phạm vi ALL/DEPARTMENT/OWN fail-closed.
