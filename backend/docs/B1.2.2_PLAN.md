## 2. Thực hiện các điều chỉnh bạn đã duyệt
| Yêu cầu | Cách làm |
|---|---|
| Trigger tham chiếu `OLD` khi INSERT | Tách: `fn_assert_lookup(id,type)` + `trg_customer_lookups_ins` (không dùng `OLD`) và `trg_customer_lookups_upd` (chỉ kiểm cột thay đổi). |
| `@default(now())` cho `updated_at` | Áp cho 6 model (`lookup_item`, `department`, `employee`, `customer`, `contact`, `activity`); `AppMeta` giữ nguyên. |
| Liên hệ phải thuộc khách hàng của hoạt động | `trg_activity_contact` (INSERT/UPDATE); thêm `trg_contact_customer_fixed` chặn chuyển khách hàng của liên hệ đã có hoạt động. |
| `ANONYMOUS` | Thêm vào `ck_audit_actor_type`; không cần `actor_employee_id`. |
| Index trùng | Bỏ `@@index([taxId])`, `@@index([email])` khỏi schema; bỏ 2 chỉ mục trigram không-bỏ-dấu (thay bằng chỉ mục bỏ dấu). Các `@@index` còn lại đã rà: không trùng tiền tố với unique/partial unique (partial index không thay thế được index thường cho FK). |
| Tìm kiếm không dấu | Extension `unaccent`; hàm `f_vn_fold(text)` (IMMUTABLE: chuẩn hoá NFC → bỏ dấu → `đ/Đ`→`d/D` → chữ thường); 3 chỉ mục GIN trigram trên biểu thức (`customer.name`, `customer.short_name`, `contact.full_name`); hàm `fn_customer_search(q, limit)` tìm theo **tên công ty, tên viết tắt, mã KH, MST, tên người liên hệ**, bỏ khách đã xoá mềm, trả `(id, score)` đã xếp hạng. Không thêm cột vào bảng nên không làm trôi lệch Prisma. |
| Hàm sinh mã tạo trước DEFAULT | Toàn bộ hàm nằm ở **PHẦN A**; script ghép chỉ cho phép thứ tự A → diff Prisma → B; kiểm tra diff có `DEFAULT fn_next_customer_code()`. |
| Qualify `public.` | Mọi hàm/trigger/sequence/chỉ mục trong SQL viết tay dùng `public.`; `"role"` được đặt trong dấu nháy. |

**Cách service sau này dùng tìm kiếm** (ghi nhận, B1.2.3+):
```sql
SELECT c.* FROM public.fn_customer_search('dien tu kim son', 50) s JOIN public.customer c ON c.id = s.id ORDER BY s.score DESC, c.name;
```
Từ khoá < 2 ký tự trả về rỗng; `% _ \` được coi là ký tự thường. Tìm theo điện thoại dùng riêng chỉ mục `ix_customer_phone_trgm` (`phone ILIKE`). Mệnh đề `OR` giữa nhiều cột khiến PostgreSQL thường quét toàn bảng; ở quy mô hàng nghìn–chục nghìn khách là chấp nhận được, sẽ đo lại khi có dữ liệu.

## 3. Bước 1 — kiểm chứng NGAY, không ghi vào database (đã đủ để bạn gửi lại kết quả)
Dừng `npm run start:dev` trước. Mở cmd:
```bat
cd /d D:\SISCOM-CRM\backend
npx prisma validate
npx prisma generate
mkdir D:\SISCOM-CRM\backups\b122
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script --output D:\SISCOM-CRM\backups\b122\b122_delta.sql
node scripts\assemble-b122-migration.cjs --diff D:\SISCOM-CRM\backups\b122\b122_delta.sql --out D:\SISCOM-CRM\backups\b122\migration_rehearsal.sql --fail-test D:\SISCOM-CRM\backups\b122\migration_fail_test.sql
```
`migrate diff --from-config-datasource` chỉ **đọc** database (soi cấu trúc). Script ghép chỉ đọc/ghi file, không kết nối database, và **từ chối** nếu:
- diff có `DROP/DELETE/TRUNCATE/UPDATE/INSERT` hoặc nhắc tới `app_meta`;
- không đúng 12 `CREATE TABLE`;
- thiếu `DEFAULT fn_next_customer_code()`;
- đường dẫn `--out` nằm trong `prisma\migrations` (trừ khi có `--allow-migrations-dir`).

Kết quả mong đợi (**chưa xác nhận**): 4 lệnh đầu thành công; diff mới khác bản cũ ở chỗ `updated_at ... DEFAULT CURRENT_TIMESTAMP` và không còn `customer_tax_id_idx`, `employee_email_idx`; script ghép in `[OK]` hai lần. Gửi tôi: chữ in ra, `b122_delta.sql`, và nếu muốn rà kỹ thì `migration_rehearsal.sql`.

## 4. Bước 2 — diễn tập trên database nháp (CHỈ sau khi bước 1 đạt và bạn báo "chạy diễn tập")
Database nháp = database do `restore-test.bat` tạo (`siscom_crm_restore_<ngày_giờ>`, chủ sở hữu `siscom_app`), **không phải** `siscom_crm_dev`. Thay `<DB_NHAP>` bằng tên in ra ở bước 3. Thay `18` nếu thư mục PostgreSQL của bạn khác.
1. Dừng backend. Chạy `scripts\windows\backup-db.bat`, rồi `scripts\windows\restore-test.bat` → ghi lại tên `<DB_NHAP>`; xác nhận in `schema_baseline = b1.1`.
2. **Thử tính nguyên tử trước** (bản cố ý lỗi) — kỳ vọng psql báo lỗi `division by zero` và **không** bảng nào được tạo:
```bat
set PSQL="C:\Program Files\PostgreSQL\18\bin\psql.exe"
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -v ON_ERROR_STOP=1 --single-transaction -f D:\SISCOM-CRM\backups\b122\migration_fail_test.sql
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -c "SELECT count(*) AS bang_moi FROM information_schema.tables WHERE table_schema='public' AND table_name IN ('customer','employee','audit_log');"
```
Kỳ vọng `bang_moi = 0`. (psql sẽ hỏi mật khẩu `siscom_app`; không dán mật khẩu vào chat.)
3. **Áp migration thật vào DB nháp:**
```bat
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -v ON_ERROR_STOP=1 --single-transaction -f D:\SISCOM-CRM\backups\b122\migration_rehearsal.sql
```
Kỳ vọng không có `ERROR`. Lỗi có thể gặp: `permission denied to create extension` (siscom_app không đủ quyền → báo tôi, không tự nâng quyền); `normalize` báo lỗi mã hoá (kiểm `SHOW server_encoding;` phải là `UTF8`).
4. **Bộ kiểm thử ràng buộc** (tự `ROLLBACK`, không để lại dữ liệu):
```bat
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -f D:\SISCOM-CRM\backend\docs\B1.2.2_CONSTRAINT_TESTS.sql
```
Kỳ vọng: cuối cùng có dòng `PASS | <số>` và **không có dòng `FAIL`**; mục "can_xem_lai" rỗng. Gửi toàn bộ chữ in ra.
5. **Sinh mã đồng thời** (20 kết nối × 50 lần; trùng mã sẽ báo lỗi khoá chính):
```bat
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -c "CREATE TABLE public.code_probe(code text PRIMARY KEY);"
echo INSERT INTO public.code_probe VALUES (public.fn_next_customer_code()); > D:\SISCOM-CRM\backups\b122\probe.sql
"C:\Program Files\PostgreSQL\18\bin\pgbench.exe" -n -h 127.0.0.1 -U siscom_app -c 20 -j 4 -t 50 -f D:\SISCOM-CRM\backups\b122\probe.sql <DB_NHAP>
%PSQL% -h 127.0.0.1 -U siscom_app -d <DB_NHAP> -c "SELECT count(*) AS tong, count(DISTINCT code) AS khac_nhau FROM public.code_probe;"
```
Kỳ vọng `tong = khac_nhau = 1000`, pgbench không báo lỗi. Bảng `code_probe` chỉ nằm trong DB nháp.
6. **Kiểm trôi lệch với Prisma** (đặt biến chỉ trong cửa sổ cmd này, không sửa `.env`; **đóng cửa sổ sau đó**):
```bat
set DATABASE_URL=postgresql://siscom_app:<MAT_KHAU_URL_ENCODED>@127.0.0.1:5432/<DB_NHAP>
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script
```
Kỳ vọng: rỗng ("empty migration"), **hoặc** chỉ gồm `DROP INDEX`/`ALTER … DROP DEFAULT` cho các đối tượng viết tay mà Prisma không biết (và bảng `code_probe`). **Ghi lại, KHÔNG áp dụng** kết quả này; gửi tôi để xếp vào ghi chú "trôi lệch chấp nhận được".
7. Gửi tôi toàn bộ kết quả các bước 2–6. Xoá database nháp **thủ công** bằng lệnh `restore-test.bat` in ra (chỉ database nháp đó).

## 5. Bước 3 — migration thật (CHƯA LÀM; chỉ khi bạn xác nhận diễn tập thành công)
1. `backup-db.bat` → `restore-test.bat` thành công → dừng backend.
2. Tạo thư mục `prisma\migrations\<mốc_thời_gian>_b1_2_crm_core\` và sinh `migration.sql` bằng `assemble-b122-migration.cjs … --allow-migrations-dir` từ **diff mới nhất** (sinh lại trên DB thật ngay trước khi ghép).
3. `npm run db:status` → `npm run db:migrate` (`migrate deploy`; không dùng `migrate dev`, `db push`, `migrate reset`) → kiểm tra 12 bảng + trigger + `migrate status` + `/health/database`.
4. `app_meta.schema_baseline = 'b1.2'` là thay đổi dữ liệu `app_meta` nên **chưa làm**; cần bạn duyệt riêng.
5. Chưa seed danh mục/nhân viên/vai trò; chưa API, Service, Authentication.

## 6. Hoàn tác có kiểm soát (cho bước 3)
- **Cách chính:** khôi phục bản `pg_dump` trước migration vào database mới, kiểm tra, rồi đổi `DATABASE_URL` (đúng quy trình `BACKUP_RESTORE.md`). Migration đã ghi vào `_prisma_migrations`, nên không hoàn tác bằng SQL rời.
- **Phụ:** nếu migration lỗi giữa chừng, kỳ vọng tự rollback toàn bộ (đã thử ở bước 2.2 trên DB nháp); khi đó chỉ cần sửa rồi chạy lại.
- `rollback_b1_2.sql` (chỉ `DROP` đối tượng mới) chỉ soạn sau diễn tập, chỉ dùng khi bảng còn rỗng và có xác nhận.

## 7. Rủi ro còn lại / chưa kiểm chứng
1. Trigger/hàm plpgsql, `f_vn_fold`, `fn_customer_search`, mọi `CHECK` mới chỉ được đọc bằng mắt; chưa chạy trên PostgreSQL 18.6.
2. `unaccent` có bỏ được dấu tiếng Việt dạng tổ hợp hay không phụ thuộc bản `unaccent.rules` của PostgreSQL 18; bài kiểm thử có ca NFC/NFD và `đ` để phát hiện.
3. `CREATE EXTENSION pg_trgm/unaccent` cần quyền; `siscom_app` là chủ database nháp nhưng có thể chưa đủ quyền trên `siscom_crm_dev` — diễn tập trên bản khôi phục phản ánh điều này (chủ sở hữu giống nhau).
4. `--single-transaction` của psql mô phỏng tính nguyên tử; cách Prisma `migrate deploy` bọc file migration chưa được thử — sẽ xác nhận bằng bản cố ý lỗi trên DB nháp trước bước 3.
5. Thư mục sao lưu mặc định hiện là `D:\SISCOM-CRM\db-backups` (script cũ). `CLAUDE.md` quy định `D:\SISCOM-CRM\backups`; chưa đổi script khi chưa được duyệt.
