# Runbook demo/nghiệm thu SISCOM CRM trên Windows (PostgreSQL thật, database thử, Chrome)

Áp dụng: `main` **sau khi PR runbook này (#185) được merge** (B1.4: tách role S1, quyền V3 hai pool, Remember Me 90 ngày). Máy: Windows 11 của owner, PostgreSQL 18 dịch vụ `127.0.0.1:5432`, Node.js ≥ 22, Chrome.
Mục tiêu: dựng **một database thử mới** (`siscom_crm_test_YYYYMMDD_HHMMSS`) đúng kiến trúc bảo mật (3 role, 2 pool), chạy backend + giao diện trên máy, nghiệm thu bằng Chrome.

**Không dùng cho:** `siscom_crm_dev`, hai baseline đã khoá (`siscom_crm_restore_20261014_214105`, `siscom_crm_restore_20261015_214948`), production, Internet. Mọi script tự từ chối các tên này.

## 0. Ảnh hưởng tới máy chủ PostgreSQL (đọc trước khi chạy)
Các thay đổi **cấp cluster** (ảnh hưởng chung cả máy chủ đang chứa `siscom_crm_dev`):
- Tạo **1 database mới**. Không xoá database nào.
- Lần đầu chạy mục 4: tạo **2 role**: `siscom_migrator` (chủ sở hữu DB thử) và `siscom_auth` (pool xác thực); cấp `SET ON PARAMETER app.actor_employee_id, app.priv_request_id` cho hai role này (`siscom_app` đã có từ B1.3); `siscom_auth` được `CONNECT` vào DB thử.
- **Bước ROLE_SPLIT tạm đổi chủ sở hữu** mọi database đang thuộc `siscom_app` (gồm `siscom_crm_dev` và 2 baseline) sang `siscom_migrator` **rồi trả lại ngay trong cùng một giao dịch** (cách PostgreSQL thực hiện `REASSIGN OWNED`). Script tự kiểm chủ sở hữu + quyền CONNECT của các DB đó trước khi xác nhận; sai lệch thì **huỷ toàn bộ**. Kết quả cuối: các DB khác giữ nguyên; nhưng danh mục hệ thống của chúng có được ghi rồi trả lại. Đã diễn tập trên cluster tạm với DB "canary" thuộc `siscom_app` (giữ nguyên chủ sở hữu và CONNECT).
- **Không chạy song song** `create-test-db`, migrate hay thao tác DB khác trong lúc chạy mục 4.
- Mật khẩu 2 role sinh ngẫu nhiên 64 ký tự, lưu ở `%LOCALAPPDATA%\SISCOM-CRM\demo\roles-5432.secrets` (ngoài repo; chỉ tài khoản Windows của anh đọc được). Không ai cần gõ hay xem.
- Trước khi tạo/đổi mật khẩu role, script **kiểm log máy chủ không ghi câu lệnh** (`log_statement = none`, `log_min_duration_statement = -1` hoặc ≥ 1000 ms); nếu đang ghi thì dừng (tránh mật khẩu vào log).
- Không đụng `.env` (chỉ đọc mật khẩu `siscom_app` trong `DATABASE_URL`).

Kiểm trước (tuỳ chọn, chỉ đọc) xem 2 role đã có chưa — trong pgAdmin/psql với `postgres`:
```sql
SELECT rolname FROM pg_roles WHERE rolname IN ('siscom_migrator', 'siscom_auth');
```

## 1. Chuẩn bị (một lần)
`D:\SISCOM-CRM` đang ở nhánh khác và có thay đổi chưa commit trong `tools\`: **không** chuyển nhánh ở đó. Dùng một thư mục làm việc riêng:
```bat
cd /d D:\SISCOM-CRM
git fetch origin
git worktree add D:\SISCOM-CRM-demo-run origin/main
cd /d D:\SISCOM-CRM-demo-run\backend
npm ci
npm run build
cd ..\frontend\siscom-crm-web
npm ci
set VITE_CRM_AUTH_ENABLED=true
set VITE_CRM_API_ENABLED=true
set VITE_CRM_API_BASE=/api/v1
npm run build
```
Kiểm: `backend\dist\main.js` và `frontend\siscom-crm-web\dist\index.html` tồn tại.
Các script đọc `.env` theo **vị trí của script** (`<thư mục>\backend\.env`); thư mục mới không có `.env` thì tự dùng `D:\SISCOM-CRM\backend\.env`. File này cần `DATABASE_URL` trỏ `siscom_app@127.0.0.1:5432/siscom_crm_dev` (chỉ đọc mật khẩu `siscom_app`, **không kết nối** `siscom_crm_dev`).

## 2. Tạo database thử
Mở `D:\SISCOM-CRM-demo-run\backend\scripts\windows`, chạy:
```bat
create-test-db.bat
```
Nhập mật khẩu `postgres` (không lưu). Ghi lại dòng **TÊN DATABASE THỬ** (dưới đây là `<DB>`).

## 3. Migrate, danh mục, tài khoản (DB còn thuộc `siscom_app`)
```bat
auth-demo-stack.bat -Step migrate   -DatabaseName <DB>
auth-demo-stack.bat -Step seed      -DatabaseName <DB>
auth-demo-stack.bat -Step bootstrap -DatabaseName <DB>
```
- Mỗi bước hỏi gõ lại tên DB để xác nhận.
- `bootstrap` hỏi mật khẩu cho 5 tài khoản (sysadmin/admin/sale/kythuat/ketoan`@siscom.local`), ≥ 12 ký tự, **mật khẩu mới** (không dùng lại bộ demo cũ đã lộ). Chỉ chạy được **một lần** cho mỗi DB.
- **Bắt buộc đủ cả 3 bước trước mục 4**: sau khi tách role, `siscom_app` không còn quyền ghi danh mục/tài khoản (đúng thiết kế). Mục 4 tự kiểm và **từ chối tách** nếu thiếu.

## 4. Tách role (khuyến nghị cho nghiệm thu bảo mật)
```bat
demo-split.bat -Step split -DatabaseName <DB>
```
Script kiểm điều kiện (chỉ đọc: đã migrate đủ, đã seed, đã bootstrap, mật khẩu role đúng, log máy chủ an toàn) rồi mới ghi: ROLE_SPLIT → AUTH_ROLE → APP_GRANTS_V3 ×2 → VERIFY (pool nghiệp vụ) → VERIFY_AUTH (pool xác thực). Kết quả đúng:
```text
[DAT] VERIFY (pool nghiep vu siscom_app) PASS|73
[DAT] VERIFY_AUTH (pool xac thuc siscom_auth) PASS|33
```
Bất kỳ dòng `KHONG DAT` nào: dừng, chụp màn hình gửi lại.

**Dừng giữa chừng** (mất điện, Ctrl-C, lỗi sau ROLE_SPLIT): chạy lại đúng lệnh trên — DB đã thuộc `siscom_migrator` thì script bỏ qua ROLE_SPLIT và làm tiếp các bước còn lại (idempotent). Nếu DB chưa bootstrap mà đã tách (không thể xảy ra với script hiện tại vì có kiểm): bỏ DB đó, tạo DB mới từ mục 2.

**Mật khẩu role không khớp / mất file mật khẩu** (`Mat khau cua siscom_migrator ... KHONG dung` hoặc `file mat khau chua co`):
```bat
demo-split.bat -Step resetpw
```
Gõ `DOI-MAT-KHAU` để xác nhận, nhập mật khẩu `postgres`. Script đặt mật khẩu ngẫu nhiên mới cho 2 role (chỉ khi log máy chủ an toàn), lưu file, đăng nhập thử. Sau đó chạy lại lệnh `split`. Lưu ý: backend đang chạy bằng mật khẩu cũ phải khởi động lại.

Kiểm lại quyền bất cứ lúc nào (không đổi quyền/dữ liệu): `demo-split.bat -Step verify -DatabaseName <DB>` (mỗi lần chạy, mã khách tự sinh tiếp theo nhảy thêm 1 — vô hại).

## 5. Chạy backend
```bat
auth-demo-stack.bat -Step start -DatabaseName <DB>
```
- DB đã tách: script tự đặt `AUTH_DATABASE_URL` (pool `siscom_auth`), in `AUTH_DATABASE_URL = siscom_auth`.
- Kiểm trong trình duyệt: `http://127.0.0.1:3000/api/v1/health/database` phải có `"authPool":"separate"`, `"leastPrivilege":true`, `"authLeastPrivilege":true`.
- Chế độ demo nội bộ: `NODE_ENV=development`, `COOKIE_SECURE=false` (http trên máy). **Không** mở ra Internet.
- Dừng: Ctrl-C trong cửa sổ đó.

## 6. Chạy giao diện
Cửa sổ dòng lệnh khác:
```bat
cd /d D:\SISCOM-CRM-demo-run\frontend\siscom-crm-web
npm run preview
```
Mở Chrome: `http://127.0.0.1:4173`.

## 8. Khi có migration mới (sau khi đã tách role)
```bat
demo-split.bat -Step migrate -DatabaseName <DB>
```
Chạy `prisma migrate deploy` bằng `siscom_migrator`, rồi **tự chạy lại V3** và VERIFY (bảng mới nhận quyền SELECT mặc định cho `siscom_app`; VERIFY B1f bắt nếu quên). Không dùng `auth-demo-stack -Step migrate` cho DB đã tách (script từ chối).

## 9. Dọn dẹp / rollback
**Dừng demo:** Ctrl-C ở cửa sổ backend và `npm run preview`.

**Xoá DB thử** (khi không cần; **anh tự** chạy, Claude không chạy lệnh xoá): pgAdmin, hoặc
```bat
psql -U postgres -h 127.0.0.1 -c "DROP DATABASE <DB>;"
```

**Gỡ hẳn 2 role** (không bắt buộc cho demo; chỉ khi bỏ kiến trúc tách role trên máy). Làm trên **DB thử cuối cùng còn lại, TRƯỚC khi xoá nó**, theo đúng thứ tự (đầu mỗi file có giải thích), từ `D:\SISCOM-CRM-demo-run\backend\docs`:
```bat
psql -X -U siscom_migrator -h 127.0.0.1 -v ON_ERROR_STOP=1 -v target_db=<DB> -d <DB> -f B1.3_S1_APP_GRANTS_V2.sql.txt
psql -X -U postgres        -h 127.0.0.1 -v ON_ERROR_STOP=1 -v target_db=<DB> -d <DB> -f B1.3_S1_AUTH_ROLE_ROLLBACK.sql.txt
psql -X -U postgres        -h 127.0.0.1 -v ON_ERROR_STOP=1 -v target_db=<DB> -d <DB> -f B1.3_S1_ROLE_SPLIT_ROLLBACK.sql.txt
```
- Bước 1 cần mật khẩu `siscom_migrator` (trong file `roles-5432.secrets`, dòng `MIGRATOR_PW=`).
- `AUTH_ROLE_ROLLBACK` chỉ xoá `siscom_auth` khi không còn DB nào dùng nó; còn DB thử khác thì giữ role (đúng thiết kế).
- `ROLE_SPLIT_ROLLBACK` **không** xoá `siscom_migrator` (trả chủ sở hữu DB thử về `siscom_app`, thu quyền SET của migrator).
- **Không xoá file mật khẩu** `%LOCALAPPDATA%\SISCOM-CRM\demo\roles-5432.secrets` khi `siscom_migrator` hoặc `siscom_auth` còn tồn tại (nếu lỡ xoá: `demo-split.bat -Step resetpw`).

## 10. Sự cố thường gặp
| Thông báo | Cách xử lý |
|---|---|
| `Khong thay file .env` | Thêm `-EnvPath D:\SISCOM-CRM\backend\.env` |
| `Thieu dist\...` | Chạy lại mục 1 (`npm run build`) |
| `Chua seed` / `Chua bootstrap` / `chua migrate du` khi tách role | Chạy đủ mục 3 rồi chạy lại mục 4 (chưa có gì bị ghi) |
| `DB da tach role ... buoc seed/bootstrap khong dung o day` | Seed/bootstrap phải trước mục 4. Tạo DB thử mới, làm lại từ mục 2 |
| `Mat khau cua siscom_migrator ... KHONG dung` / `file mat khau chua co` | `demo-split.bat -Step resetpw` rồi chạy lại |
| `Log server dang ghi cau lenh` | Đặt `log_statement = none`, `log_min_duration_statement = -1` (postgresql.conf), reload dịch vụ, chạy lại |
| `Duong dan repo co ky tu khong phai ASCII` | Đặt thư mục làm việc ở đường dẫn chỉ có chữ không dấu, vd `D:\SISCOM-CRM-demo-run` |
| `VERIFY ... KHONG DAT` | Dừng, gửi ảnh chụp. Không sửa tay quyền DB |
| Backend báo thiếu quyền / 500 khi đăng nhập có tích | DB vừa migrate mà chưa chạy lại V3: `demo-split.bat -Step migrate` hoặc `-Step split` |
| Đăng nhập có tích lỗi sau khi đổi giờ máy | Đồng bộ giờ Windows (máy ứng dụng và DB lệch > 5 phút bị DB chặn) |

## 11. Bằng chứng diễn tập (trước khi giao)
Diễn tập toàn bộ mục 2–7 trên cluster PostgreSQL **tạm cách ly** (`127.0.0.1:55432`, dữ liệu giả, chỉ có sẵn `siscom_app` + DB canary như máy owner) bằng chính các script này, chế độ không tương tác: `docs/evidence/b1.4_demo_windows_runbook_20261101/`. Các bước nhập tay (gõ lại tên DB, nhập mật khẩu) và cổng mặc định 5432/3000 chưa được diễn tập tự động.
