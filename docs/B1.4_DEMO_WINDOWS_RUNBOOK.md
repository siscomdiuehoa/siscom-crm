# Runbook demo/nghiệm thu SISCOM CRM trên Windows (cụm PostgreSQL demo RIÊNG, database thử, Chrome)

Áp dụng: `main` sau khi PR "demo cụm PostgreSQL riêng" được merge (B1.4: tách role S1, quyền V3 hai pool, Remember Me 90 ngày). Máy: Windows 11 của owner, PostgreSQL 18 đã cài (chỉ dùng **chương trình** `initdb`/`pg_ctl`/`psql` trong `C:\Program Files\PostgreSQL\18\bin`), Node.js ≥ 22, Chrome.

**Nguyên tắc:** bản demo chạy trên **một cụm PostgreSQL 18 riêng** (thư mục dữ liệu `D:\SISCOM-CRM-demo-pg\data`, cổng **55433**, chỉ nghe `127.0.0.1`). **Không** đụng PostgreSQL hiện tại ở cổng **5432** (dịch vụ Windows chứa `siscom_crm_dev` và các baseline): không tạo DB, không tạo role, không đổi quyền, không migrate ở đó.

## 0. Hàng rào chống chạy nhầm cụm
- Cụm demo được gắn nhãn `cluster_name = 'siscom_demo'` khi khởi tạo. Mọi script ghi DB (`create-test-db`, `auth-demo-stack`, `demo-split`) **kiểm nhãn này trước khi ghi**; cụm khác nhãn (gồm cụm 5432) → dừng, không ghi gì.
- Mọi script demo (`demo-pg`, `demo-setup`, `demo-run`, `create-test-db`, `auth-demo-stack`, `demo-split`) **từ chối `-PgPort 5432`**; cổng mặc định là 55433.
- `demo-pg` từ chối thư mục dữ liệu nằm trong `C:\Program Files\PostgreSQL` hoặc trùng thư mục dữ liệu của dịch vụ PostgreSQL hiện tại; từ chối `init` nếu thư mục đã có dữ liệu, cổng đang có tiến trình nghe, hoặc file mật khẩu của cổng đó đã tồn tại. `start`/`stop`/`status` chỉ chạy khi `postgresql.conf` của thư mục có `cluster_name = 'siscom_demo'` và `port = <PgPort>` (cụm đang chạy: cổng trong `postmaster.pid` phải khớp, khác 5432) — không thể dừng nhầm cụm chính.
- Mật khẩu `postgres` của cụm demo chỉ lấy từ file của cụm demo (không hỏi tay, không lấy biến môi trường); mọi lệnh `psql` bắt buộc xác thực SCRAM (`PGREQUIREAUTH`), không gửi mật khẩu dạng rõ.
- Thư mục dữ liệu cụm demo (tạo mới bằng `init`) chỉ tài khoản Windows của anh truy cập được.
- Tên DB thử bắt buộc `siscom_crm_test_YYYYMMDD_HHMMSS`; `siscom_crm_dev` và hai baseline khoá luôn bị từ chối.
- Công tắc `-AllowMainCluster` (bỏ kiểm nhãn/cổng) **chỉ** dùng khi owner phê duyệt riêng bằng văn bản; runbook này không dùng.

Đã kiểm (bằng chứng `docs/evidence/b1.4_demo_isolated_pg_20261101/`): 6 script đều trả mã 1 với `-PgPort 5432` và không mở kết nối tới 5432; 3 script ghi DB đều trả mã 1 trên một cụm tạm không có nhãn và không tạo DB nào.

## 1. Chuẩn bị (một lần)
`D:\SISCOM-CRM` đang ở nhánh khác và có thay đổi chưa commit trong `tools\`: **không** chuyển nhánh ở đó. Dùng thư mục làm việc riêng:
```bat
cd /d D:\SISCOM-CRM
git fetch origin
git worktree add D:\SISCOM-CRM-demo-run origin/main
cd /d D:\SISCOM-CRM-demo-run\backend
npm ci
cd ..\frontend\siscom-crm-web
npm ci
```
(Đã có `D:\SISCOM-CRM-demo-run` từ lần trước: `cd /d D:\SISCOM-CRM-demo-run && git fetch origin && git checkout --detach origin/main`, rồi `npm ci` ở hai thư mục như trên.)
Không cần `.env`: cụm demo có file cấu hình riêng (mục 2).

## 2. Dựng bản demo (một lệnh)
```bat
cd /d D:\SISCOM-CRM-demo-run\backend\scripts\windows
demo-setup.bat
```
Gõ `TAO-DEMO` để xác nhận. Script làm lần lượt, dừng ngay khi một bước lỗi:
1. Chưa có cụm demo → `demo-pg init`: `initdb` (xác thực `scram-sha-256`, không `trust`), cổng 55433, nhãn `siscom_demo`, `log_statement = none`, tạo role `siscom_app`. Mật khẩu `postgres`/`siscom_app` sinh ngẫu nhiên, lưu `D:\SISCOM-CRM-demo-pg\private\pg-55433.secrets` và `demo-55433.env` (ngoài repo, chỉ tài khoản Windows của anh đọc được). Đã có cụm → `demo-pg start`.
2. Build backend + giao diện nếu chưa có (`-Build` để build lại).
3. Tạo DB thử mới `siscom_crm_test_<thời điểm>` → migrate → danh mục chuẩn → tạo 5 tài khoản demo.
4. Tách role (3 role, 2 pool) + kiểm quyền: phải thấy
   ```text
   [DAT] VERIFY (pool nghiep vu siscom_app) PASS|73
   [DAT] VERIFY_AUTH (pool xac thuc siscom_auth) PASS|33
   ```
5. Ghi tên DB demo hiện hành vào `D:\SISCOM-CRM-demo-pg\private\current-55433.txt`.

**Mật khẩu 5 tài khoản demo** sinh ngẫu nhiên (24 ký tự) và lưu ở `D:\SISCOM-CRM-demo-pg\private\accounts-<DB>.txt` (chỉ tài khoản Windows của anh đọc được). Mở bằng Notepad để lấy mật khẩu:
| Email | Vai trò |
|---|---|
| `admin@siscom.local` | crm_admin (toàn quyền CRM) |
| `sale@siscom.local` | sales (khách của mình) |
| `kythuat@siscom.local` | technician (đọc theo phòng) |
| `ketoan@siscom.local` | accountant (đọc tất cả) |
| `sysadmin@siscom.local` | quản trị kỹ thuật |

Mọi file mật khẩu/cấu hình demo nằm ở **`D:\SISCOM-CRM-demo-pg\private`** (không dùng `%LOCALAPPDATA%`: khi script được chạy từ một ứng dụng đóng gói MSIX như Claude desktop, Windows chuyển hướng ghi `AppData` vào thư mục riêng của ứng dụng đó nên anh mở `%LOCALAPPDATA%` sẽ không thấy file).

Chạy lại `demo-setup.bat` = tạo **thêm một DB demo mới** (DB cũ giữ nguyên trên cụm demo); `demo-run` dùng DB mới nhất.

## 3. Chạy demo
```bat
demo-run.bat
```
- Khởi động cụm demo (nếu đang dừng), mở cửa sổ **"SISCOM demo backend"** (cổng 3100) và **"SISCOM demo web"** (cổng 4173), rồi mở Chrome `http://127.0.0.1:4173`.
- Script kiểm `http://127.0.0.1:3100/api/v1/health/database` có `"authPool":"separate"`, `"leastPrivilege":true`, `"authLeastPrivilege":true` và in `[DAT] Backend: 2 pool ...`.
- Chế độ demo nội bộ: `NODE_ENV=development`, cookie không `Secure` (http trên máy). **Không** mở ra Internet.
- **Dừng:** đóng 2 cửa sổ trên, rồi `demo-pg.bat -Step stop`. Lần sau chỉ cần `demo-run.bat`.
- Trạng thái cụm: `demo-pg.bat -Step status`.

## 4. Checklist nghiệm thu trên Chrome
| # | Thao tác | Kết quả đúng |
|---|---|---|
| 1 | Đăng nhập `admin@siscom.local` (không tích ghi nhớ) | Vào trang khách hàng; tạo/sửa khách được |
| 2 | Đăng xuất; đăng nhập `sale@siscom.local` | Chỉ thấy khách của mình; tạo được khách mới |
| 3 | `kythuat@siscom.local` | Đọc theo phòng; không tạo/sửa khách |
| 4 | `ketoan@siscom.local` | Đọc tất cả; không tạo/sửa |
| 5 | Đổi mật khẩu (menu "Đổi mật khẩu") | Thành công; mật khẩu cũ không đăng nhập được (ghi lại mật khẩu mới — file `accounts-<DB>.txt` không tự cập nhật) |
| 6 | Đăng nhập **có tích** "Ghi nhớ đăng nhập trên thiết bị này (tối đa 90 ngày)" | Vào được bình thường |
| 7 | Đóng hẳn Chrome, mở lại `http://127.0.0.1:4173` | Vẫn đăng nhập |
| 8 | F12 → Application → Cookies → `http://127.0.0.1:4173` → xoá **chỉ** cookie `siscom_sid` → F5 | Tự vào lại, không hỏi mật khẩu; F12 → Network thấy `remember/restore` trả 200 |
| 9 | Đăng xuất rồi F5 | Phải nhập mật khẩu (ghi nhớ bị huỷ) |
| 10 | Đăng nhập **không** tích ghi nhớ; xoá `siscom_sid` như mục 8; F5 | Phải nhập mật khẩu |

Lưu ý: mỗi máy được tối đa **5 lần thử đăng nhập / 15 phút cho cùng một tài khoản** (tính cả lần đúng — chống dò mật khẩu). Đăng nhập/đăng xuất liên tục cùng một tài khoản sẽ gặp "Quá nhiều lần thử"; đợi 15 phút hoặc dùng tài khoản khác.

Kiểm tự động (tuỳ chọn): `frontend/siscom-crm-web/tests/browser/sessionRolesChrome.mjs` với `E2E_API=http://127.0.0.1:3100` và biến `BOOTSTRAP_PASSWORD_ADMIN/_SALE/_TECHNICIAN/_ACCOUNTANT` đúng mật khẩu hiện tại.

## 5. Khi có migration mới (DB demo đã tách role)
```bat
demo-split.bat -Step migrate -DatabaseName <DB>
```
Chạy `prisma migrate deploy` bằng `siscom_migrator`, tự chạy lại V3 và VERIFY. Hoặc đơn giản: `demo-setup.bat` tạo DB demo mới từ đầu.

Kiểm lại quyền (không đổi quyền/dữ liệu): `demo-split.bat -Step verify -DatabaseName <DB>`.
Mật khẩu role `siscom_migrator`/`siscom_auth` của cụm demo nằm ở `D:\SISCOM-CRM-demo-pg\private\roles-55433.secrets`; mất file → `demo-split.bat -Step resetpw` (chỉ ảnh hưởng cụm demo).

## 6. Dọn dẹp / rollback
Cụm demo **độc lập** với PostgreSQL 5432, nên gỡ bỏ không ảnh hưởng `siscom_crm_dev`:
1. Dừng demo: đóng 2 cửa sổ, `demo-pg.bat -Step stop`.
2. Xoá (**anh tự làm**; Claude không chạy lệnh xoá): cả thư mục `D:\SISCOM-CRM-demo-pg` (gồm `data` và `private` chứa mọi file mật khẩu demo).
3. Muốn dựng lại từ đầu: chạy lại `demo-setup.bat` sau bước 2 (`demo-pg init` từ chối thư mục đã có dữ liệu hoặc file mật khẩu cũ còn tồn tại).

Xoá riêng một DB demo cũ trên cụm demo (tuỳ chọn): `psql -h 127.0.0.1 -p 55433 -U postgres -c "DROP DATABASE <DB>;"` (mật khẩu `postgres` ở dòng `POSTGRES_PW=` trong `pg-55433.secrets`). Không bao giờ chạy lệnh này với `-p 5432`.

## 7. Sự cố thường gặp
| Thông báo | Cách xử lý |
|---|---|
| `Cong 5432 la PostgreSQL hien tai...` | Đúng thiết kế: bỏ `-PgPort 5432`, dùng mặc định 55433 |
| `Cum PostgreSQL dang ket noi co cluster_name = ...` | Cổng đang trỏ sai cụm. Kiểm `demo-pg.bat -Step status`; không dùng `-AllowMainCluster` |
| Cổng 55433 đang có tiến trình nghe (khi init) | Có chương trình khác dùng cổng này: dùng `-PgPort` khác (và `-DataDir` khác) cho **mọi** script, kể cả `demo-pg.bat -Step status/stop -PgPort 55434` |
| `Khong co file mat khau cum demo (...pg-<port>.secrets)` | Cụm demo chưa init xong hoặc file đã bị xoá. Script **không** hỏi mật khẩu `postgres` (tránh gõ nhầm mật khẩu cụm 5432). `demo-pg init` dừng giữa chừng: dừng cụm (`demo-pg.bat -Step stop`), xoá thư mục dữ liệu, chạy lại `demo-setup.bat` |
| `... khong phai cum demo (thieu cluster_name = siscom_demo)` khi start/stop/status | `-DataDir` không trỏ cụm demo (ví dụ thư mục data của PostgreSQL 5432): đúng thiết kế, sửa `-DataDir` |
| Thư mục dữ liệu đã có (khi init) | Cụm demo đã tồn tại: `demo-setup` tự `start`; muốn làm lại từ đầu xem mục 6 |
| `Thieu ban build` | `demo-setup.bat -Build` |
| `backend chua co node_modules` | `npm ci` (mục 1) |
| `Cong 3100/4173 dang co dich vu` | Demo đang chạy: đóng cửa sổ backend/web cũ trước |
| `Backend khong len sau 60 giay` | Xem cửa sổ "SISCOM demo backend" |
| `VERIFY ... KHONG DAT` | Dừng, gửi ảnh chụp. Không sửa tay quyền DB |
| "Quá nhiều lần thử" khi đăng nhập | Hạn mức 5 lần/15 phút/tài khoản (mục 4): đợi 15 phút |
| "Đăng nhập thất bại." dù mật khẩu đúng (F12 → Network: `auth/login` trả 403) | Lỗi đã biết BUG-1 (cookie phiên cũ còn sót, ví dụ sau khi dựng DB demo mới hoặc đổi mật khẩu ở trình duyệt khác). F12 → Application → Cookies → `http://127.0.0.1:4173` → xoá `siscom_sid` rồi đăng nhập lại |
| Đăng nhập có tích lỗi sau khi đổi giờ máy | Đồng bộ giờ Windows |
