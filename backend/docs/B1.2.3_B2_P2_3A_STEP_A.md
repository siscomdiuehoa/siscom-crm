## Nội dung
- **A0 – tách chi phí 100.000 liên hệ:** (quét) / (+`f_vn_fold`) / (+`similarity`), mỗi loại 2 lần EXPLAIN ANALYZE (lấy lần 2). Suy ra `foldMs`, `similarityMs`, microseconds mỗi liên hệ. Đây là **trần cải thiện** của A1/A2: phần CPU này không giảm bằng cách gom theo tập.
- **A2 – 5 từ khóa × 3 biến thể:** `nguyen van`, `mi`, `an` + đối chứng `cumperf`, `minh phat`; biến thể **S0** (truy vấn API hiện tại, đường UNION hoặc OR do `chooseSearchPath`), **A1** (`WITH cand0 AS MATERIALIZED` toàn bộ tập khớp, gom `max(similarity)` theo `customer_id` chỉ trên liên hệ của tập đó, `LEFT JOIN`), **A2** (gom toàn bộ `contact`, `LEFT JOIN`). Mỗi biến thể: 1 EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) + 1 warm-up + 5 lần đo; ghi min/median/max, node chính (Seq Scan, SubPlan và số vòng lặp, Aggregate/HashAggregate, Sort, CTE Scan), shared hit/read, temp.
- **A3 – so khớp tuyệt đối với S0:** với `nguyen van`, `mi`, `an` × quyền ALL/OWN/DEPARTMENT × relevance DESC/ASC (đối chứng chỉ ALL): so **tổng và TOÀN BỘ ID đúng thứ tự** (LIMIT 100.000); với ALL còn so trang 1, 2, giữa, cuối, vượt cuối. Công thức relevance, `c.code DESC`, `count(*) OVER ()`, điều kiện quyền giữ nguyên; **không giới hạn tập ứng viên trước khi tính điểm/sắp xếp**. Khác dù một ID ⇒ test FAIL (exit ≠ 0).
- **A4 – trang 100 danh sách:** 3 vòng × 15 mẫu, ghi **p95 và median từng vòng** cho: HTTP trang 1, HTTP trang 100, `prisma.customer.count`, `findMany` skip 0 và skip 1.980 (kèm quan hệ), SQL chỉ lấy id với OFFSET 1.980; cùng EXPLAIN của COUNT, id offset 0 và offset 1.980. Cho phép tách OFFSET / COUNT / nạp quan hệ / dao động. (Điều kiện danh sách lấy gần đúng cho quyền ALL, không thay log Prisma.)

## Cổng quyết định (chỉ là cổng kỹ thuật mức SQL, KHÔNG thay ngưỡng API 500/1.500 ms)

## Cách đọc báo cáo
1. `dataUnchanged = true`, `activeSessionsAfter = 0`, `failures` rỗng; `equality.mismatches = 0`.
2. `a0.derived`: `foldMs`, `similarityMs`, `perContactMicros`.
3. `timings[term][S0|A1|A2]`: `timesMs`, `median`, `max`, `plan.subPlans` (S0: vòng lặp ≈ số khách khớp; A1/A2: không còn SubPlan), `plan.aggregates`, `plan.sorts`, `plan.seqScans`, `rootSharedHit`.
4. `gateVerdict`: biến thể nào qua cổng.
5. `page100`: so `httpPage100` với `httpPage1`; nếu `prismaFindMany_skip1980` ≈ `skip0` và `sqlIdsOnly_offset1980` nhỏ ⇒ OFFSET không phải nguyên nhân; xem `p95PerRound` có vòng bất thường (nhiễu) không.
