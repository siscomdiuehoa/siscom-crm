## 1. Vấn đề (S1 đóng trong PR này; S2 mở, S3 mở một phần — xem §7)
`siscom_app` hiện là **chủ sở hữu** database và mọi bảng/hàm (Windows `setup-db.ps1`, CI `pg-temp-db.sh`). Chủ sở hữu có thể `ALTER TABLE … DISABLE TRIGGER`, `DROP TRIGGER`, `CREATE OR REPLACE` hàm trigger, `GRANT` lại quyền cho chính mình ⇒ **mọi lớp bảo vệ trong DB (trigger audit B7, guard M1/M1.1, S3 credential) đều vượt qua được từ ứng dụng** nếu ứng dụng bị chiếm (SQLi, RCE). M1.2 đã thu `EXECUTE` các `fn_auth_api_*` khỏi PUBLIC và ghi rõ sẽ cấp lại cho app bằng script S1 — script chưa tồn tại.

## 2. Thiết kế
| Role | Quyền | Dùng cho |
|---|---|---|
| `siscom_migrator` | LOGIN, NOSUPERUSER, NOCREATEROLE; **chủ sở hữu** database + mọi bảng/sequence/hàm/extension; `SET` tham số `app.*` | `prisma migrate deploy/status/diff` (qua `MIGRATE_DATABASE_URL`), `npm run auth:bootstrap` (gọi `fn_auth_bootstrap_close` — chỉ chủ sở hữu), chạy script GRANT, runbook vận hành |
| `siscom_app` | CONNECT + TEMP (không CREATE) trên DB; USAGE (không CREATE) schema `public`; SELECT/INSERT/UPDATE/DELETE mọi bảng **trừ** `audit_log` (chỉ SELECT/INSERT) và `_prisma_migrations` (chỉ SELECT); USAGE/SELECT/UPDATE sequence; EXECUTE `fn_auth_api_*`; **không** EXECUTE `fn_auth_bootstrap_close`; `SET` tham số `app.*` | Backend chạy (`DATABASE_URL`), test integration |
| Quyền mặc định | `ALTER DEFAULT PRIVILEGES FOR ROLE siscom_migrator IN SCHEMA public`: bảng ⇒ DML, sequence ⇒ USAGE/SELECT/UPDATE cho app | Migration tương lai không cần GRANT tay; bảng chỉ-thêm mới phải tự REVOKE (mẫu B1.2 B8 — khối `DO` chạy khi `current_user <> siscom_app`, tức đúng khi migrate bằng migrator) |

Mã ứng dụng không đổi: `backend/src` không dùng `SET ROLE`, `DISABLE TRIGGER`, `set_config` ngoài hàm DB (grep). Chỉ thêm lớp chọn URL cho CLI.

## 4. Kiểm thử — thứ tự trên CI (`backend-pg`, DB tạm `siscom_crm_test_<stamp>`)
1. `create` (DB **owner = siscom_app**, mô hình cũ) → `migrate deploy` bằng app (như trước) → status/drift.
2. **RED:** `B1.3_S1_VERIFY` chạy bằng app, mode `fail` ⇒ phải có `FAIL|n` (app còn DISABLE TRIGGER, CREATE, là chủ sở hữu…).
3. **Tách:** `split` (ROLE_SPLIT superuser → APP_GRANTS migrator) → **GREEN:** `VERIFY` mode `res` ⇒ `PASS|41`, không FAIL.
4. `migrate status`/`diff` bằng migrator (`MIGRATE_DATABASE_URL`) và bằng app (chỉ đọc).
5. Ràng buộc M1/M1.1 bằng app (DML), **M1.2 bằng migrator** (file tự yêu cầu chủ sở hữu), M1.3 cấu trúc.
6. **Rollback đầy đủ:** `unsplit` → M1.3→M1.2→M1.1→M1 rollback (bằng app, lúc này là chủ sở hữu — đúng guard "chủ sở hữu phải là siscom_app" của file rollback M1.2) → `migrate deploy` lại bằng app → `split` lại → VERIFY PASS.
7. `migrate deploy` (không còn migration chờ) bằng migrator ⇒ thoát 0.
8. Integration (`test:e2e:customers`) trên DB **đã tách role**: ứng dụng = app; bootstrap/ALTER DATABASE qua migrator; `db-roles.int-spec` 6 ca.

**Máy làm việc (không PostgreSQL):** tsc OK · unit **397/397** (392 + 5) tại thời điểm đó; sau khi gộp main (P1+P2) và các sửa rà soát: **423/423** (CI `b2c51c0`) · build OK · `prisma validate` nạp `prisma.config.ts` import TS OK, từ chối `postgres` đúng · `bash -n` 2 script OK.
