# B1.5 — Runbook: thử SISCOM CRM trên điện thoại trong Wi-Fi nội bộ (phương án B: CA nội bộ mkcert)

Owner chọn **B** ngày 01/11/2026 (xem `docs/B1.5_MOBILE_LAN_PLAN.md`). Tài liệu này là các bước **anh tự làm hoặc phê duyệt từng bước**; script `backend\scripts\windows\demo-lan.ps1` **không** tải phần mềm, **không** tạo quy tắc firewall, **không** cài CA.

Nguyên tắc: chỉ cụm PostgreSQL demo 55433 (từ chối 5432); backend `127.0.0.1:3100`, giao diện `127.0.0.1:4173` **vẫn chỉ loopback**; duy nhất Caddy nghe `https://<IP Wi-Fi>:8443`. Không mở ra Internet.

## 0. Kiểm tra trước (chỉ đọc)
```bat
D:\SISCOM-CRM\backend\scripts\windows\demo-lan.bat -Step check
```
In ra: IP Wi-Fi và hồ sơ mạng (Private/Public), những thứ còn thiếu, Caddyfile sẽ dùng, và **lệnh firewall** để anh chạy ở mục 4. Không thay đổi gì.

## 1. Mạng
- Máy tính và điện thoại cùng Wi-Fi nội bộ (không dùng Wi-Fi khách/công cộng). IP máy hiện tại: `192.168.1.10` (DHCP — có thể đổi; `-Step check` in IP hiện tại; **nếu đổi**: làm lại chứng chỉ mục 3 **và** tạo lại/sửa quy tắc firewall mục 4 vì `-LocalAddress` không còn khớp; muốn cố định IP thì đặt "DHCP reservation" trên router — thay đổi mạng, anh quyết).
- Hồ sơ mạng hiện là **Public**. Hai lựa chọn (anh quyết): (a) đổi mạng này sang **Private** (Cài đặt → Mạng & Internet → Wi-Fi → mạng đang dùng → "Mạng riêng tư"); hoặc (b) giữ Public và dùng quy tắc firewall `-Profile Public` như script in ra (vẫn giới hạn dải IP nội bộ + chương trình caddy.exe).

## 2. Tải công cụ (cần anh cho phép **cả hai**; em không tự tải)
Thư mục: `D:\SISCOM-CRM-lan-tools\` (file mới).
| Công cụ | Nguồn chính thức | Kiểm tra |
|---|---|---|
| `caddy.exe` (bản chính thức, Windows amd64) | github.com/caddyserver/caddy/releases (file `caddy_<ver>_windows_amd64.zip`) | so SHA-256 với file `*_checksums.txt` cùng bản phát hành: `Get-FileHash .\caddy_<ver>_windows_amd64.zip -Algorithm SHA256` |
| `mkcert.exe` | github.com/FiloSottile/mkcert/releases (file `mkcert-v<ver>-windows-amd64.exe`) | so SHA-256 với bản phát hành (trang release ghi checksum) |
Không cần cài đặt; không thêm vào PATH.

## 3. Chứng chỉ (CA nội bộ) — chạy trên máy anh, dữ liệu để trong `private` (**cần anh duyệt**: bước này tạo một **khoá riêng CA** `CA\rootCA-key.pem` trên máy; ai có khoá này có thể giả mọi trang HTTPS trên điện thoại đã cài CA)
```powershell
$env:CAROOT = 'D:\SISCOM-CRM-demo-pg\private\lan-certs\CA'      # CA de trong thu muc private (ACL chi owner), KHONG o AppData
New-Item -ItemType Directory -Force $env:CAROOT | Out-Null
Set-Location 'D:\SISCOM-CRM-demo-pg\private\lan-certs'
D:\SISCOM-CRM-lan-tools\mkcert.exe 192.168.1.10                 # tao CA (lan dau) + chung chi cho IP Wi-Fi; KHONG dung -install
```
Kết quả: `192.168.1.10.pem`, `192.168.1.10-key.pem` (Caddy dùng) và `CA\rootCA.pem` (cài lên điện thoại). **Không chạy `mkcert -install`** (sẽ ghi CA vào kho tin cậy Windows — chỉ làm nếu anh muốn trình duyệt trên máy tính không cảnh báo; đó là thay đổi hệ thống, cần anh quyết riêng). Khoá riêng `CA\rootCA-key.pem` **không** rời máy; xoá cả thư mục `lan-certs` khi kết thúc giai đoạn thử.

## 4. Firewall (anh chạy PowerShell **Administrator**; lệnh chính xác do `-Step check` in ra)
```powershell
New-NetFirewallRule -DisplayName "SISCOM demo LAN 8443" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -LocalAddress 192.168.1.10 -RemoteAddress 192.168.1.0/24 -Profile Private -Program "D:\SISCOM-CRM-lan-tools\caddy.exe"
```
(`-Profile Public` nếu giữ hồ sơ Public.) Nếu Windows hiện hộp thoại "Cho phép ứng dụng qua tường lửa" khi Caddy chạy: **bấm Hủy** (bấm Cho phép sẽ tạo quy tắc rộng).

## 5. Chạy
```bat
D:\SISCOM-CRM\backend\scripts\windows\demo-lan.bat -Step start
```
Script: kiểm cụm demo + DB + build + chứng chỉ → `caddy validate` → mở 3 cửa sổ (backend LAN: `COOKIE_SECURE=true`, `TRUST_PROXY=loopback`, origin `https://192.168.1.10:8443`; web; Caddy) → **tự kiểm cổng lắng nghe**: chỉ `192.168.1.10:8443` mở ra Wi-Fi, 3100/4173/55433 chỉ loopback; sai là dừng ngay.

## 6. Điện thoại
1. Đưa `CA\rootCA.pem` lên điện thoại (AirDrop/USB/email nội bộ — chỉ file `.pem` của CA, **không** gửi file `-key.pem`).
2. iPhone: mở file → Cài đặt → Hồ sơ đã tải về → Cài đặt; rồi **Cài đặt → Cài đặt chung → Giới thiệu → Cài đặt tin cậy chứng nhận** → bật cho "mkcert …". Android: Cài đặt → Bảo mật → Mã hoá & thông tin xác thực → Cài đặt chứng chỉ → Chứng chỉ CA.
3. Safari/Chrome mở `https://192.168.1.10:8443` → đăng nhập tài khoản demo (`D:\SISCOM-CRM-demo-pg\private\accounts-<DB>.txt`). Làm theo `docs/B1.5_OWNER_ACCEPTANCE_CHECKLIST.md`.
4. "Thêm vào màn hình chính" để dùng như ứng dụng (PWA manifest là PR riêng, bước 4 của kế hoạch).

## 7. Kiểm thử bảo mật bắt buộc (em làm sau khi anh duyệt mục 2–4; ghi bằng chứng vào `docs/evidence/`)
- Từ thiết bị khác trong Wi-Fi: `https://192.168.1.10:8443` mở được; `192.168.1.10:3100`, `:4173`, `:55433`, `:5432` **không** kết nối được.
- Cookie `siscom_sid`, `siscom_rmb`, `siscom_csrf` có `Secure`; POST thiếu `X-CSRF-Token` hoặc Origin lạ ⇒ 403; `/api/v1/health/database` → `authPool=separate`.
- Hạn mức đăng nhập tính theo IP điện thoại (`TRUST_PROXY=loopback`): thử sai 5 lần từ điện thoại không khoá đăng nhập từ máy tính.
- Chrome headless qua HTTPS (bộ 4 vai trò + Remember Me): Chrome trên máy tính **không** tin CA mkcert (vì không `mkcert -install`) ⇒ harness phải chạy với cờ `--ignore-certificate-errors` **chỉ trong tiến trình thử** (không tắt kiểm chứng chỉ ở đâu khác), hoặc anh duyệt `mkcert -install` (ghi CA vào kho tin cậy Windows). **Cần anh chọn** trước khi em chạy bộ này.
- Lưu ý: Caddy chỉ mở TCP (`protocols h1 h2`, không HTTP/3 UDP); script tự kiểm `netstat` sau khi khởi động và **tự dừng Caddy** nếu có cổng nghe ngoài dự kiến.

## 8. Kết thúc buổi thử
Đóng 3 cửa sổ (LAN proxy, backend, web) → `Disable-NetFirewallRule -DisplayName "SISCOM demo LAN 8443"` (Administrator) → `demo-pg.bat -Step stop` (nếu không dùng demo nữa). Hết giai đoạn thử: `Remove-NetFirewallRule …`, gỡ hồ sơ CA khỏi điện thoại, xoá `lan-certs`.

## 9. Chưa làm / không tự làm
Chưa tải Caddy/mkcert, chưa tạo CA/chứng chỉ, chưa tạo quy tắc firewall, chưa đổi hồ sơ mạng, chưa cài gì lên điện thoại. PostgreSQL 5432 không đụng. Không deploy.
