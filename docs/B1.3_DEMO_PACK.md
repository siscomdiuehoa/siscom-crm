# B1.3 — Bộ demo MVP: đăng nhập thật bằng phiên cookie + 4 vai trò (PR 5/5)

Mục đích: dựng **backend thật** (NestJS, PR #167) + **giao diện chính thức** (`frontend/siscom-crm-web`, PR #168) trên một **database thử cách ly** để (1) demo đăng nhập/đăng xuất/phân quyền cho 4 vai trò của ma trận V2 và (2) chạy harness Chrome thật `sessionRolesChrome.mjs` lấy bằng chứng. Mọi thứ chỉ chạy trên `127.0.0.1`; **không bao giờ** đụng `siscom_crm_dev` hay các baseline đã khoá.

| Thành phần | Yêu cầu |
|---|---|
| PostgreSQL | 18 (hoặc ≥ 15), dịch vụ chạy ở `127.0.0.1:5432`, đã có tài khoản `siscom_app` (từ `setup-db.bat`) |
| Node | ≥ 22 (máy hiện tại: 24) |
| Trình duyệt | Chrome hoặc Edge đã cài (harness tự tìm; hoặc `BROWSER_EXE`) |
| Mật khẩu `postgres` | chỉ dùng ở bước A (tạo DB thử), nhập ẩn, không lưu |

Quy ước bảo mật (AGENTS.md): script chỉ **đọc** `backend\.env` để lấy mật khẩu `siscom_app`, đưa cho tiến trình con qua biến môi trường, không in, không ghi log; tên DB thử phải khớp `^siscom_crm_(restore|test)_\d{8}_\d{6}$` và được đối chiếu `current_database()` trước mọi bước ghi. Mật khẩu tài khoản thử do bạn tự đặt (≥ 12 ký tự), không ghi vào file nào trong repo.

## A. Tạo database thử rỗng (một lần)
Nhấp đúp `backend\scripts\windows\create-test-db.bat` → nhập mật khẩu `postgres`. Script tạo `siscom_crm_test_<ngày>_<giờ>` (OWNER `siscom_app`, UTF8, `TEMPLATE template0`, `REVOKE ALL FROM PUBLIC`) và in **TÊN DATABASE THỬ**. Giữ tên này cho các bước sau (gọi là `<DB>`).

Tuỳ chọn `-GrantSetParameter`: `GRANT SET ON PARAMETER app.actor_employee_id, app.priv_request_id TO siscom_app` (phạm vi toàn cluster, điều kiện triển khai M1.2 ghi ở PR #166). **Không cần** cho đăng nhập/khách hàng; chỉ cần nếu sau này gọi `fn_auth_api_*`.

## B. Áp schema (migrate deploy)
```bat
backend\scripts\windows\auth-demo-stack.bat -Step migrate -DatabaseName <DB>
```
Gõ lại tên DB để xác nhận. Chạy `prisma migrate deploy` + `migrate status` (chỉ các migration đã có trong repo, gồm M1→M1.3). Kỳ vọng: cả hai mã thoát 0, "Database schema is up to date".

## C. Tạo 4+1 tài khoản thử (bootstrap, một lần)
Trước đó build backend: `cd backend && npm run build`. Rồi:
```bat
backend\scripts\windows\auth-demo-stack.bat -Step bootstrap -DatabaseName <DB>
```
Script hỏi ẩn 5 mật khẩu (hoặc đặt sẵn `BOOTSTRAP_PASSWORD_SYSADMIN/ADMIN/SALE/TECHNICIAN/ACCOUNTANT` trong cửa sổ lệnh). Cuối cùng in mã nhân viên (ví dụ `NV-0001`…). Bootstrap đóng chế độ khởi tạo M1 vĩnh viễn cho DB này (chạy lại ⇒ `BOOTSTRAP_CLOSED`, không sao, dùng tài khoản cũ).

| Khoá | Email đăng nhập | Vai trò DB | Nhãn trên giao diện | Phòng | Dùng trong demo |
|---|---|---|---|---|---|
| `ADMIN` | `admin@siscom.local` | `crm_admin` | Quản trị CRM | BGD | Toàn quyền khách hàng (ALL), duyệt M1 |
| `SALE` | `sale@siscom.local` | `sales` | Kinh doanh | KD | Phạm vi OWN |
| `TECHNICIAN` | `kythuat@siscom.local` | `technician` | Kỹ thuật | KT | Chỉ đọc theo phòng (DEPARTMENT) |
| `ACCOUNTANT` | `ketoan@siscom.local` | `accountant` | Kế toán | KETOAN | Chỉ đọc toàn bộ (ALL) |
| `SYSADMIN` | `sysadmin@siscom.local` | `admin` (kỹ thuật M1) | Quản trị hệ thống | IT | Không có quyền nghiệp vụ; không dùng trong demo |

Đăng nhập được bằng email **hoặc** mã `NV-xxxx`.

## D. Chạy backend thật trên DB thử (giữ cửa sổ mở)
```bat
backend\scripts\windows\auth-demo-stack.bat -Step start -DatabaseName <DB>
```
Backend nghe `http://127.0.0.1:3000/api/v1`, `COOKIE_SECURE=false` (http nội bộ), `CORS_ORIGINS` = `AUTH_ALLOWED_ORIGINS` = FE cổng 5173 và 4173. Kiểm tra nhanh: `auth-demo-stack.bat -Step status` → `HTTP 200`.

## E. Chạy giao diện (cùng origin qua proxy `/api`)
Trong `frontend\siscom-crm-web` (cửa sổ `cmd` mới):
```bat
set VITE_CRM_AUTH_ENABLED=true
set VITE_CRM_API_ENABLED=true
set VITE_CRM_API_BASE=/api/v1
npm run dev
```
→ mở `http://127.0.0.1:5173` (dev server proxy `/api` → backend 3000). Để chạy harness, dùng bản build + preview thay cho `dev`:
```bat
npm run build
npm run preview
```
→ `http://127.0.0.1:4173` (preview cũng proxy `/api`). Không đặt cờ ⇒ giao diện quay về chế độ demo localStorage như cũ.

## F. Kịch bản demo tay (theo vai trò)
| Bước | Thao tác | Kỳ vọng |
|---|---|---|
| F1 | Mở FE khi chưa đăng nhập | Màn hình đăng nhập (AuthGate); không vào được dữ liệu |
| F2 | Sai mật khẩu | Banner "Thông tin đăng nhập không đúng", vẫn ở màn hình đăng nhập (5 lần sai liên tiếp ⇒ khoá 15 phút — **tránh** trên tài khoản demo) |
| F3 | `admin@siscom.local` | Banner "Đang đăng nhập: Quản trị CRM (NV-…)", vai trò "Quản trị CRM"; Khách hàng: thêm/sửa/xoá mềm/khôi phục được |
| F4 | Tải lại trang (F5) | Vẫn đăng nhập (khôi phục qua `/auth/me`; CSRF lấy lại từ cookie `siscom_csrf`) |
| F5 | Đăng xuất | Về màn hình đăng nhập; tải lại vẫn ở màn hình đăng nhập |
| F6 | `ketoan@siscom.local` | Thấy toàn bộ khách (ALL) kể cả khách admin vừa tạo; không có nút thêm/sửa/xoá |
| F7 | `kythuat@siscom.local` | Danh sách rỗng (DEPARTMENT; khách do admin tạo chưa có chủ sở hữu/phòng) |
| F8 | `sale@siscom.local` | Danh sách rỗng (OWN); bấm "Thêm khách hàng" ⇒ máy chủ trả 403 (**D12**: tạo khách cần scope ALL tới khi có B3 `CustomerAssignment`) — hạn chế đã biết, không phải lỗi |
| F9 | Mở DevTools → Application → Cookies | `siscom_sid` HttpOnly, SameSite=Lax, Path=/api/v1; `siscom_csrf` không HttpOnly; **không** có token trong localStorage |

## G. Harness Chrome thật (bằng chứng tự động)
Backend (D) và FE preview (E, cổng 4173) đang chạy. Trong `frontend\siscom-crm-web`:
```bat
set BOOTSTRAP_PASSWORD_ADMIN=<mật khẩu đã đặt ở C>
set BOOTSTRAP_PASSWORD_SALE=...
set BOOTSTRAP_PASSWORD_TECHNICIAN=...
set BOOTSTRAP_PASSWORD_ACCOUNTANT=...
node tests\browser\sessionRolesChrome.mjs
```
Harness chạy Chrome headless (CDP cổng 9355, chỉ loopback), kịch bản S0–S8 cho 4 vai trò, **ghi 1 khách hàng** vào DB thử (bằng `crm_admin`) để chứng minh phạm vi đọc, rồi ghi bằng chứng JSON (không bí mật) vào `docs\evidence\b1.3_e2e_session_roles_<thời điểm>.json` và in bảng PASS/FAIL/KNOWN. Mã thoát 0 = đạt, 1 = có FAIL, 2 = BLOCKED (thiếu backend/FE/mật khẩu/trình duyệt). Biến tuỳ chọn: `E2E_WEB`, `E2E_API`, `E2E_EMAIL_DOMAIN`, `E2E_EVIDENCE`, `E2E_CDP_PORT`, `BROWSER_EXE`.

| Mã | Kiểm tra |
|---|---|
| S0 | Chưa đăng nhập: màn hình đăng nhập, `/auth/me` 401, không cookie |
| S1 | Sai mật khẩu: banner lỗi, vẫn 401 |
| S2.x | Đăng nhập từng vai trò: banner tên + mã NV, `/auth/me` đúng vai trò, quyền `customer.*`/`contact.*`/`lookup.read` **đúng ma trận V2**, nhãn vai trò, cookie `siscom_csrf` đọc được; admin: thuộc tính cookie `siscom_sid`/`siscom_csrf` |
| S3.x | Danh sách khách hàng tải từ máy chủ (UI không lỗi, API 200) |
| S4.admin | POST không CSRF ⇒ 403 `CSRF_FAILED`; CSRF sai ⇒ 403; đúng ⇒ 201 và khách hiện trên UI |
| S4.sale | POST với CSRF đúng ⇒ 403 (KNOWN, D12) |
| S5.x | Phạm vi đọc: ALL thấy khách admin tạo; OWN/DEPARTMENT không thấy |
| S6.x | Tải lại trang: phiên khôi phục, `/auth/me` 200 |
| S7.x | Đăng xuất: 401, cookie xoá |
| S8 | Không lỗi console/ngoại lệ JS |

CI **không** chạy harness này (cần PostgreSQL + backend thật + trình duyệt); bằng chứng được commit thủ công cùng PR.

## H. Dọn dẹp / rollback
- Dừng backend (Ctrl-C), dừng FE. Không có gì được ghi ngoài `<DB>` và thư mục `docs\evidence`.
- Xoá DB thử khi không cần (bạn tự chạy, cần mật khẩu `postgres`): `DROP DATABASE <DB>;`. Có thể giữ để demo lại (tài khoản đã bootstrap còn nguyên).
- `siscom_crm_dev`, `siscom_crm_restore_20261014_214105`, `siscom_crm_restore_20261015_214948`: không bị đụng ở bất kỳ bước nào.

## I. Hạn chế đã biết (MVP)
1. **D12**: `sales` tạo khách ⇒ 403 cho tới B3 `CustomerAssignment` (gán chủ sở hữu). Khách do `crm_admin` tạo không có chủ sở hữu ⇒ OWN/DEPARTMENT không thấy.
2. Chưa có đổi/đặt lại mật khẩu trên giao diện (`fn_auth_api_*`, PR sau); chưa có `AccessGuard` theo route.
3. `COOKIE_SECURE=false` chỉ cho demo http nội bộ; production bắt buộc `true` + HTTPS.
4. Khoá tài khoản sau 5 lần sai (15 phút, luỹ tiến) — hạn mức trong bộ nhớ reset khi backend khởi động lại; khoá trong DB thì không.
