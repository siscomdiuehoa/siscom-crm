# B1.5 — Kế hoạch VPS: staging riêng, sau đó production (CHỈ KẾ HOẠCH + DỰ TOÁN, CHƯA THUÊ/TRIỂN KHAI)

Owner quyết định 01/11/2026: **có staging riêng**; chưa chọn nhà cung cấp/tên miền; **staging dùng dữ liệu giả, không sao chép database thật**; chỉ lập kế hoạch và dự toán.

## 1. Kiến trúc (giống bản demo đã nghiệm thu, thêm HTTPS)
```
Internet ──443──> Caddy (TLS Let's Encrypt, HSTS, gzip)
                    ├── /            -> file tĩnh giao diện (dist)
                    └── /api/*       -> backend Node (127.0.0.1:3000, systemd, TRUST_PROXY=loopback)
                                           ├── pool nghiệp vụ  siscom_app  ─┐
                                           └── pool xác thực   siscom_auth ─┴─> PostgreSQL 18 (127.0.0.1:5432 TRÊN VPS, không mở ra ngoài)
                                                                                 chủ sở hữu/migrate: siscom_migrator
```
- **Hai môi trường tách biệt**: `staging` và `production` (khuyến nghị 2 VPS riêng; tối thiểu 2 database + 2 dịch vụ trên cùng VPS nếu cần tiết kiệm — kém an toàn hơn).
- Cùng origin (giao diện + API cùng tên miền) ⇒ cookie đăng nhập, CSRF, Remember Me giữ nguyên cơ chế; `COOKIE_SECURE=true` (production bắt buộc theo `env.validation`), `CORS_ORIGINS`/`AUTH_ALLOWED_ORIGINS` = `https://<tên miền>`.
- Tên miền gợi ý: `crm.<tên-miền-công-ty>` (production), `crm-staging.<tên-miền-công-ty>` (staging, có thể chặn theo IP văn phòng).

## 2. Bảo mật
| Lớp | Biện pháp |
|---|---|
| Mạng | Firewall chỉ mở 443 (và 80 để chuyển hướng/ACME); SSH đổi cổng, **chỉ khoá SSH**, tắt đăng nhập root bằng mật khẩu; fail2ban |
| TLS/cookie | HTTPS bắt buộc + HSTS; áp tiền tố cookie `__Host-` (nghiên cứu: `docs/B1.4_SECURITY_RESEARCH_HOST_COOKIE_RESTORE_RETRY.md`) |
| Database | PostgreSQL chỉ nghe `127.0.0.1`; 3 role (migrator/app/auth) + V3 + VERIFY/VERIFY_AUTH như demo; `log_statement=none` |
| Bí mật | File môi trường quyền `600`, chủ là user dịch vụ; không đưa vào Git; xoay vòng mật khẩu khi nghi lộ |
| Hệ điều hành | Ubuntu LTS, `unattended-upgrades` cho bản vá bảo mật; user dịch vụ riêng không có quyền sudo |
| Ứng dụng | `NODE_ENV=production`; hạn mức đăng nhập theo IP thật (`TRUST_PROXY=loopback`); theo dõi nhật ký đăng nhập thất bại |
| Staging | Dữ liệu giả; không chung mật khẩu với production; có thể giới hạn IP văn phòng |

## 3. Sao lưu và khôi phục (production; staging chỉ cần bản chụp VPS)
- `pg_dump` (định dạng custom) mỗi đêm + mã hoá (age/gpg) + đẩy ra **kho lưu trữ ngoài VPS** (S3-compatible của nhà cung cấp khác).
- Giữ: 7 bản ngày, 4 bản tuần, 6 bản tháng. Tuỳ chọn WAL archiving nếu cần khôi phục theo thời điểm.
- **Diễn tập khôi phục mỗi tháng** vào database thử (tên `siscom_crm_restore_*`), kiểm số dòng + VERIFY.

## 4. Dự toán chi phí (THAM KHẢO, cần báo giá thực tế khi chọn nhà cung cấp)
| Hạng mục | Staging | Production | Ghi chú |
|---|---|---|---|
| VPS | 2 vCPU / 4 GB / 60–80 GB SSD: ~250.000–500.000 đ/tháng | 4 vCPU / 8 GB / 100–160 GB SSD: ~600.000–1.200.000 đ/tháng | Nhà cung cấp trong nước (Viettel IDC, VNPT, FPT Cloud, BizFly…) hoặc quốc tế vùng Singapore |
| Tên miền | dùng chung | ~300.000 đ/năm (nếu chưa có) | |
| Chứng chỉ TLS | 0 đ (Let's Encrypt) | 0 đ | |
| Kho sao lưu ngoài | — | ~50.000–150.000 đ/tháng | tuỳ dung lượng |
| Giám sát/uptime | 0 đ (gói miễn phí) | 0–100.000 đ/tháng | |
| **Ước tính** | **~0,3–0,5 triệu đ/tháng** | **~0,7–1,5 triệu đ/tháng** | chưa gồm VAT |
Lưu ý pháp lý: dữ liệu khách hàng là dữ liệu cá nhân (Nghị định 13/2023/NĐ-CP) — cân nhắc đặt máy chủ tại Việt Nam và ghi nhận quy trình xử lý dữ liệu; đề nghị owner xác nhận với bộ phận pháp lý.

## 5. Các bước chuyển đổi (mỗi bước chờ owner duyệt)
1. Owner chọn nhà cung cấp + tên miền (em chuẩn bị bảng so sánh 3 báo giá nếu cần).
2. Em viết hạ tầng dưới dạng script/tài liệu trong Draft PR (cài đặt, Caddy, systemd, PostgreSQL, role, sao lưu) — **chưa chạy**.
3. Owner thuê VPS staging; em dựng staging bằng script, dữ liệu giả (`demo-setup` tương đương trên Linux).
4. Kiểm thử trên staging qua HTTPS: toàn bộ harness Chrome (4 vai trò, Remember Me, người liên hệ, tỉnh/thành), kiểm cookie `Secure`/`__Host-`, quét cổng từ ngoài (chỉ 443/80/SSH).
5. Owner nghiệm thu staging (checklist người dùng, cả trên điện thoại).
6. Quyết định dữ liệu khởi đầu production (trống / nhập từ file / chuyển từ database nào — **chưa sao chép DB thật khi chưa có phê duyệt riêng**).
7. Dựng production, sao lưu chạy thử + diễn tập khôi phục **trước** khi mở cho người dùng.
8. Mở truy cập; theo dõi 2 tuần đầu.

## 6. Chưa làm
Chưa thuê VPS, chưa mua tên miền, chưa tạo tài khoản nhà cung cấp, chưa tạo bản ghi DNS, chưa triển khai gì.
