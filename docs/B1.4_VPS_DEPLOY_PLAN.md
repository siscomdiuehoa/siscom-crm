## 1. Kiến trúc đề xuất (1 VPS, đơn giản nhất đủ dùng)

```
Người dùng (trình duyệt) ──HTTPS 443──▶ nginx (TLS Let's Encrypt)
                                          ├─ /            → file tĩnh FE  /var/www/siscom-crm/dist
                                          └─ /api/        → http://127.0.0.1:3000 (giữ nguyên đường dẫn /api/v1, giữ header Origin)
                                                             backend NestJS (systemd, user siscom, 1 instance, Node 24)
                                                               └─ PostgreSQL 18 cùng máy, chỉ localhost (role siscom_app DML; siscom_migrator owner)
```

| Thành phần | Đề xuất | Lý do |
|---|---|---|
| OS | Ubuntu Server 24.04 LTS, 2 vCPU / 4 GB RAM / 40 GB SSD (đủ cho nội bộ; tăng sau) | Hỗ trợ dài hạn, gói PGDG cho PostgreSQL 18, Node 24 qua NodeSource |
| Reverse proxy | **nginx** (phương án B: Caddy — tự TLS, ít cấu hình hơn; owner chọn) | Cùng origin cho cookie `siscom_sid` (`Path=/api/v1`, HttpOnly, Lax) và `siscom_csrf` (`Path=/`); CORS backend để `credentials:false` nên **bắt buộc cùng origin** |
| TLS | Let's Encrypt (certbot), bắt buộc vì `COOKIE_SECURE=true` ở production | `env.validation` cấm `COOKIE_SECURE=false` khi `NODE_ENV=production` |
| Backend | `node dist/main.js` qua systemd, `EnvironmentFile=/etc/siscom-crm/backend.env` (quyền 600), `HOST=127.0.0.1`, `PORT=3000`, `Restart=on-failure` | Không lộ cổng 3000 ra ngoài; limiter trong bộ nhớ ⇒ **chỉ 1 instance** |
| PostgreSQL | 18 (PGDG), `listen_addresses='localhost'`, `pg_hba` chỉ `127.0.0.1/32` và `::1/128`, DB `siscom_crm_prod` UTF8/template0, extension `pg_trgm`, `unaccent` | Giống môi trường đã nghiệm thu; không PgBouncer (PgBouncer có thể lặng lẽ bỏ tham số khởi động `TimeZone=UTC` của D.0) |
| Múi giờ | Hệ điều hành và PostgreSQL để UTC (ứng dụng tự ép `TimeZone=UTC` + `DateStyle=ISO` mọi kết nối); `systemd-timesyncd` bật | D.0: tránh lệch đồng hồ DB/ứng dụng (cùng máy) |
| Tường lửa | ufw: chỉ 22 (SSH khoá công khai, tắt mật khẩu), 80, 443; fail2ban cho SSH | Bề mặt tấn công tối thiểu |
| Sao lưu | `pg_dump -Fc` hằng đêm 02:00 (giờ VN) → `/var/backups/siscom-crm/`, giữ 14 bản ngày + 8 bản tuần; chép ngoài máy chủ (owner chọn nơi: ổ NAS công ty / object storage); thử khôi phục hằng tháng vào DB `siscom_crm_restore_<ts>` | Theo `BACKUP_RESTORE.md`, chuyển từ `.ps1` sang bash |

**Quy trình cập nhật sau go-live** (`deploy.sh`): tag mới trên `main` (CI xanh, owner duyệt) → thông báo bảo trì → `backup-db.sh` → `git fetch && checkout <tag>` → `npm ci && npm run build` → `prisma migrate deploy` (chỉ khi có migration mới, đã thử trên bản khôi phục của production trước) → build FE nếu đổi → `systemctl restart` → health + smoke. **Lùi:** checkout tag cũ + restart; nếu đã migrate thì khôi phục DB từ bản sao lưu vừa tạo (migration là cộng thêm nên thường không cần).

## 6. Cấu hình mẫu (giá trị thật điền trên máy chủ, không commit)

`/etc/siscom-crm/backend.env` (root:siscom, 600):
```
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
DATABASE_URL=postgresql://siscom_app:<mật-khẩu>@127.0.0.1:5432/siscom_crm_prod        # KHÔNG có tham số options
CORS_ORIGINS=https://<domain>
AUTH_ALLOWED_ORIGINS=https://<domain>
COOKIE_SECURE=true
TRUST_PROXY=loopback
LOG_LEVEL=log
SESSION_IDLE_MINUTES=480
SESSION_ABS_HOURS=12
LOGIN_WINDOW_MINUTES=15
LOGIN_MAX_PER_SOURCE=30
LOGIN_MAX_PER_IDENTIFIER=5
LOGIN_LOCK_AFTER_FAILURES=5
LOGIN_LOCK_MINUTES=15
```
`MIGRATE_DATABASE_URL` (siscom_migrator) chỉ đặt tạm trong phiên shell khi chạy `migrate deploy`, không ghi vào file env của dịch vụ. `JWT_*`, `ACCESS_TTL_*`, `REFRESH_*` không cần (di sản, không dùng).

`/etc/systemd/system/siscom-crm-backend.service`:
```
[Unit]
Description=SISCOM CRM backend
After=network-online.target postgresql.service
Wants=network-online.target
[Service]
User=siscom
Group=siscom
WorkingDirectory=/opt/siscom-crm/backend
EnvironmentFile=/etc/siscom-crm/backend.env
ExecStart=/usr/bin/node dist/main.js
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadOnlyPaths=/opt/siscom-crm
PrivateTmp=true
[Install]
WantedBy=multi-user.target
```

nginx `/etc/nginx/sites-available/siscom-crm` (certbot sẽ thêm khối 443/TLS):
```
server {
  listen 80;
  server_name <domain>;
  root /var/www/siscom-crm/dist;
  index index.html;
  client_max_body_size 1m;
  location /api/ {
    proxy_pass http://127.0.0.1:3000;          # giữ nguyên /api/v1/...
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Request-Id $request_id;
    # Origin được chuyển tiếp mặc định — KHÔNG ghi đè, CsrfOriginGuard cần
  }
  location / { try_files $uri $uri/ /index.html; }
}
```

Lệnh build FE: `cd frontend/siscom-crm-web && npm ci && VITE_CRM_AUTH_ENABLED=true VITE_CRM_API_ENABLED=true VITE_CRM_API_BASE=/api/v1 npm run build`.

## 7. Rủi ro còn lại và cách giảm

| Rủi ro | Giảm nhẹ |
|---|---|
| Chưa có luồng admin đặt lại mật khẩu (Minor 11): người dùng quên mật khẩu | Quy trình vận hành: owner duyệt trên Issue, chạy hàm M1.2 (yêu cầu đặc quyền → mã reset) bằng `siscom_migrator` trên máy chủ theo runbook; không sửa `password_hash` tay |
| Limiter trong bộ nhớ, 1 instance | Chấp nhận cho nội bộ; P1 làm hạn mức theo IP thật; khoá tài khoản bền trong DB |
| Node 24 / PostgreSQL 18 còn mới | Ghim phiên bản; chỉ cập nhật bản vá; theo dõi EOL |
| Dữ liệu cũ lệch 7 giờ (D.0) | Không áp dụng: production là DB mới (Q7) |
| Mật khẩu demo đã lộ | Không dùng tài khoản demo trên production; mật khẩu bootstrap production do owner đặt trên máy chủ |
| Sao lưu chưa thử trên Linux | G6 bắt buộc restore-test PASS trước go-live |
| `app_meta.updated_at` không múi giờ, Prisma Studio theo múi giờ máy chủ | Máy chủ để UTC ⇒ trùng ứng dụng |
| Một VPS, không HA | Chấp nhận cho MVP nội bộ; sao lưu ngoài máy chủ + runbook khôi phục ≤ 1 giờ |

## 8. Những gì em KHÔNG làm nếu owner chưa duyệt
Không mua/cấu hình VPS, không trỏ DNS, không cài gì lên máy chủ, không tạo DB production, không chạy migration/seed/bootstrap ngoài DB thử, không merge PR, không đổi dữ liệu vận hành, không mở rộng chức năng.
